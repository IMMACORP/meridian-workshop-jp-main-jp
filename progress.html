3.第2幕：R1 の修正

3.1　原因

フィルターの配線は正常でした。FilterBar.vue → useFilters.js → watch → loadData() → api.js → FastAPI の経路はすべて正しく動作しており、API を直接叩くとフィルターに応じた値が返っていました。

問題は KPI カードが取得済みのデータを使わず固定値を表示していたことです。ordersData.value と fillRate.value への代入は、コード全体に1箇所もありませんでした。

KPI カードの状態（修正前 → 修正後）
KPI修正前修正後の算出式
在庫回転率テンプレートに 4.2 を直書きΣ受注明細 quantity ÷ Σ在庫 quantity_on_hand
受注充足数ref({ fulfilled: 187, goal: 200 })status が Delivered / Shipped の件数
受注充足率ref(96.8)充足件数 ÷ 全受注件数 × 100
売上summary.total_orders_value（正常）変更なし
平均処理日数テンプレートに 2.8 を直書き既存 orderHealthMetrics.avgFulfillmentDays を再利用

目標値は「件数と期間あたりの率は期間フィルターで按分し、比率(%)と日数は按分しない」という基準で統一しました。画面下部のドーナツチャート・カテゴリー別・受注推移・在庫上位・バックログは、もとから正しく反応していました。

3.3　コードレビューで追加修正した点

サブエージェント（code-reviewer）のレビューを受け、スコープ内の指摘を修正しました。

  • loadData が成功時に error をリセットしていなかった — 一度 API が失敗すると、以降フィルターを変えて取得に成功しても画面が復帰しません。「フィルターを変えても更新されない」症状を生む既存バグでした
  • status / 日付が欠損したデータで computed が例外や NaN を起こしうる箇所にガードを追加
  • 対象0件のときに 0 ではなく — を表示 — 平均処理日数が 0 だと「目標より速い」と誤読されるため、「データなし」と「実績ゼロ」を区別
  • 受注充足数の進捗バーだけ 100% で頭打ちになっておらず、月次フィルターで超過するとバーがはみ出していた
  • loadData 内のローカル変数が同名の computed をシャドウしていた
レビュー指摘のうち、対応しなかったもの

「revenueGoal の通貨換算漏れ」は誤りでした。formatCurrency が USD→JPY 換算を行っています（表示の ¥1,440,000,000 = 9.6M × 150）。

進捗バーの意味の逆転は意図的な挙動としてコメントを残すに留めました。平均処理日数 8.7日（目標3.0日、+191%）でバーが満タンになりますが、「小さいほど良い」指標のバー表現を変えるのは KPI カードの設計変更にあたり、R1 のスコープ外と判断しています。数値と差分は正しく表示されています。
